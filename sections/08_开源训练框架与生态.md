# 8. 开源训练框架 / 生态

> **评价标准提醒**：本分块的多数条目是 `工程框架`，其价值在于**接口设计、数据格式标准化、可复现性与社区采纳度**，而不是 benchmark 数字。用评价"方法论文"的标准（是否 SOTA）来评价框架是错误的。

本分块解决的核心问题是：**让 VLA 从"每家自己写一套训练脚本"变成有共享数据格式、可插拔组件与可复现基线的工程生态。** 生态目前分三层：**数据层**（RLDS / LeRobotDataset —— 决定数据能否跨机构复用）、**模型与训练层**（Prismatic → OpenVLA、openpi、StarVLA —— 决定实验能否公平比较）、**部署层**（LeRobot 的硬件驱动、openpi 的服务端推理 —— 决定研究能否上真机）。

未解决的瓶颈：（1）**数据格式仍然分裂**（RLDS/TFDS 与 LeRobotDataset/parquet 两套并存，转换有损）；（2）**评测未被框架化**——大多数框架能训练但不能一键复现论文数字；（3）**真机部署层缺乏标准**（每台机器人的标定、安全限位、控制接口各写各的）；（4）**框架的维护寿命短**，很多 2024 年的框架已停止更新。

**技术演进链：**

`RLDS（跨机构数据格式）→ Prismatic VLMs（可控的 VLM 训练底座）→ OpenVLA（首个完整开源 VLA 训练栈）→ openpi（flow matching VLA 的开源权重与推理服务）→ LeRobot / SmolVLA（低成本硬件 + 数据 + 训练 + 部署全链条）→ StarVLA（乐高式解耦：backbone × action head × benchmark 任意组合）`

- **RLDS → Prismatic**：前者统一了"数据长什么样"，后者统一了"VLM 怎么训、消融怎么做"，二者共同构成 OpenVLA 得以出现的前提。
- **Prismatic → OpenVLA**：把 VLM 训练栈接上机器人动作数据与 OXE 加载器，形成第一个"下载即可复现论文"的 VLA 栈。
- **OpenVLA → openpi**：开源的重心从"复现学术模型"转向"**发布工业级预训练权重 + 推理服务**"，让小团队能在自己的机器人上微调 π0/π0.5。
- **openpi → LeRobot**：把门槛进一步下降到**几百美元的硬件（SO-100/SO-101）+ 单卡训练（SmolVLA 450M）**，并统一了数据集格式与 Hub 分发。
- **LeRobot → StarVLA**：解决"组件不可组合"的问题——把 backbone、action head、benchmark 三个维度解耦，使消融实验可在统一代码下进行。

## 生态选型建议（面向本库研究方向）

| 需求 | 首选 | 理由 |
|---|---|---|
| 复现学术 VLA 基线、做 LIBERO 消融 | OpenVLA / OpenVLA-OFT + LIBERO | 社区数字最多、对比最直接 |
| 在自己的真机上微调强模型 | openpi（π0.5） | 唯一开源的工业级 flow matching 权重 |
| 低成本采数据、快速迭代 | LeRobot + SO-101 + SmolVLA | 全链条最短、单卡可训 |
| 做 backbone × action head 的系统消融 | StarVLA（**核实后再投入**） | 唯一显式提供组合空间的框架 |
| 跨机构复用他人数据 | LeRobotDataset（新）/ RLDS（旧，OXE 必需） | 二者互转有损，需提前确定主格式 |
