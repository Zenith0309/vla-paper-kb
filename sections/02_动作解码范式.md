# 2. 动作解码范式

本分块回答的是：**给定多模态编码后的隐状态，用什么形式把它变成物理可执行的动作序列。** 这是 VLA 领域争议最集中、迭代最快的部分。四条主线并存：**离散 token 自回归**（可直接复用 LLM 词表与训练基础设施，但受量化分辨率与逐 token 解码速度限制）、**连续回归**（快、稳，但难以建模多模态动作分布）、**diffusion / flow matching**（能表达多模态分布、适合高频灵巧动作，但需多步去噪）、**VQ / 频域压缩 token**（在 token 化的框架内提高信息密度）。

一个已被反复验证的正交结论是：**action chunking（一次预测 H 步）比逐步预测更稳**，因为它抑制了复合误差与人类演示中的时序抖动；而 chunk 带来的新问题是**执行期间的策略滞后**，由此催生了 temporal ensembling 与异步实时推理。

未解决的瓶颈：（1）**没有统一的动作表示评测**，各家在不同 benchmark 上自证优越；（2）**chunk 长度、执行比例、重规划频率**是强超参，缺乏理论指导；（3）**diffusion/flow 的多步推理与实时性**的矛盾尚未彻底解决（一步蒸馏方案的稳定性未被大规模验证）。

**技术演进链：**

`RT-1（离散 bin token）→ VQ-BeT（VQ 分层 token）→ π0-FAST（DCT 频域 token）→ CogACT / Dita（diffusion action expert）→ OpenVLA-OFT（并行连续回归 + chunk）→ Real-Time Chunking（异步执行，见第 12 类）`

- **RT-1 → VQ-BeT**：从"每个自由度独立均匀分 bin"变为"用残差 VQ 学出动作码本"，把多模态动作分布的建模从分箱精度问题变成码本表达力问题，且天然支持 chunk。
- **VQ-BeT → π0-FAST**：从"学出来的码本"变为"DCT + BPE 的无学习频域压缩"，把 50 步动作块压到约 30 个 token，训练速度较朴素分箱快约 5 倍，且跨本体通用（无需重训 tokenizer）。
- **π0-FAST → CogACT / Dita**：放弃 token 化，改由独立的 diffusion/DiT 动作专家在连续空间去噪，彻底摆脱量化误差，代价是引入迭代推理。
- **CogACT/Dita → OpenVLA-OFT**：反向验证"**不需要 diffusion 也行**"——用并行解码 + L1 回归 + chunk，在 LIBERO 上既更准又快 26 倍，说明此前的性能差距很大程度来自 chunk 与并行解码而非 diffusion 本身。
- **OpenVLA-OFT → RTC**：把问题从"怎么生成 chunk"推进到"chunk 执行期间怎么无缝衔接下一个 chunk"，即推理延迟下的动作连续性。

## 动作表示速查表

| 表示 | 代表工作 | 优点 | 主要代价 | 典型控制频率 |
|---|---|---|---|---|
| 均匀分箱离散 token | RT-1, RT-2, OpenVLA | 复用 LLM 词表与训练栈 | 量化误差、逐 token 解码慢、忽略维度相关性 | 1–10 Hz |
| 学习式 VQ token | VQ-BeT, LAPA | 建模多模态分布、支持 chunk | 码本需重训、跨本体差 | 10–100 Hz |
| 频域压缩 token（DCT+BPE） | π0-FAST | 无需学习、跨本体通用、token 数少 5–10 倍 | 仍是自回归解码，高频细节有损 | 10–50 Hz |
| 连续回归（L1/L2） | OpenVLA-OFT | 最快、最稳、易训练 | 无法建模多模态动作分布 | 25–100 Hz |
| Diffusion | Diffusion Policy, CogACT, Dita, GR00T N1 | 多模态分布表达力最强 | 多步去噪、实时性差 | 10–50 Hz（需加速） |
| Flow matching | π0, π0.5, SmolVLA | 比 diffusion 步数少、训练稳定 | 仍需迭代；一步蒸馏稳定性待验证 | 50 Hz |

> **执行期技巧（与表示正交）**：action chunking（ACT）、temporal ensembling（ACT）、adaptive action ensemble（CogACT）、real-time chunking / 异步推理（RTC，见第 12 类）。这些技巧的增益经常与表示本身的增益混淆，阅读消融表时需特别注意。
