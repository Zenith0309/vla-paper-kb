# 7. 仿真环境与评测基准

本分块解决的核心问题是：**在真机评测昂贵、不可复现、各家 setup 不同的现实下，如何建立可比较的策略评估协议。** 三类 benchmark 需要严格区分，不能用同一标准评价：**simulation benchmark**（RLBench、CALVIN、LIBERO、RoboCasa、RoboTwin——完全在仿真中训练与评测，优点是可复现，缺点是与真机分布差距大）、**real-to-sim 代理评测**（SimplerEnv——用仿真近似特定真机 setup，目的是预测真机排名而非绝对成功率）、**real-world benchmark**（DROID 评测集、各家自建真机套件——最有说服力但几乎不可跨机构复现）。

已被广泛接受的事实：**LIBERO 已趋于饱和**（多个 VLA 在四套件上超过 95%，区分度下降），因此 2025 年后的工作转向 **鲁棒性维度扩展**（LIBERO-Plus 加入 7 类扰动）与 **更难的双臂/长程/杂乱场景**（RoboTwin 2.0、RoboCasa）。

未解决的瓶颈：（1）**仿真-真机排名相关性**除 SimplerEnv 外几乎无人系统研究；（2）**成功率之外的指标缺失**——安全性、平滑度、恢复能力、语言遵循度都没有标准度量；（3）**评测协议的自由度太大**（相机位姿、初始化范围、最大步数、是否允许重试），导致论文间数字不可直接比较；（4）**语言维度的评测极弱**——绝大多数 benchmark 的指令模板化，无法检验开放世界语言理解与指代消歧。

**技术演进链：**

`RLBench（多任务仿真 + 关键帧动作）→ CALVIN（长程语言指令 + 未见环境泛化）→ LIBERO（终身学习/四类分布迁移，成为 VLA 事实标准）→ SimplerEnv（real-to-sim 代理评测，把仿真数字与真机排名对齐）→ RoboCasa（大规模厨房场景 + 生成式资产 + 自动数据生成）→ RoboTwin 2.0（双臂 + 强域随机化 + 数据生成器一体化）`

- **RLBench → CALVIN**：从"任务库"转向"**长程语言链**"——一条指令序列包含 5 个连续子任务，且训练/测试环境划分（ABC→D）专门检验环境泛化。
- **CALVIN → LIBERO**：把泛化维度**解耦为四个可控轴**（Spatial / Object / Goal / Long），使"模型在哪种分布迁移上失败"可被单独诊断，这是它成为标准的关键。
- **LIBERO → SimplerEnv**：问题从"仿真里谁强"变为"**仿真里的排名能否预测真机排名**"，通过视觉/动力学匹配把 Google Robot 与 WidowX 真机 setup 迁入仿真。
- **SimplerEnv → RoboCasa**：把场景规模从桌面提升到**完整厨房环境（120 场景、2500+ 物体资产、生成式 3D 资产）**，并内置 MimicGen 式自动数据扩增。
- **RoboCasa → RoboTwin 2.0**：面向**双臂协作**，把"benchmark"与"数据生成器"合二为一，并沿 5 个轴（杂乱、光照、背景、桌高、语言）做强域随机化，直接服务于 sim-to-real。

## 交叉标签

- **RLBench** → 交叉：`3D 关键帧策略（PerAct）`、`模仿学习基础`
- **CALVIN** → 交叉：`长程规划`、`world model（GR-1 主战场）`
- **LIBERO** → 交叉：`几乎所有 VLA 方法论文`、`RL post-training`、`鲁棒性（LIBERO-Plus）`
- **SimplerEnv** → 交叉：`真机评测代理`、`跨本体对比`
- **RoboCasa** → 交叉：`数据生成`、`人形（GR00T）`、`仿真 scaling`
- **RoboTwin 2.0** → 交叉：`数据生成`、`双臂/RDT 生态`、`sim-to-real 鲁棒性`

## 引用 benchmark 数字时的检查清单

1. **图像分辨率与相机数量**是否一致（LIBERO 上 128 vs 224 分辨率差距显著）。
2. 是否使用 **proprioception**（OpenVLA 默认不用，OFT 用，数字不可直接比）。
3. **最大步数**与是否允许失败重试。
4. **训练数据规模**（从头训 vs 大规模预训练后微调）。
5. **随机种子数量与评测 episode 数**（很多论文只跑 50 episode，置信区间很宽）。
6. 报告的是**相对提升**还是**绝对成功率**。
