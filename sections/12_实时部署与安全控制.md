# 12. 实时部署、安全与具身控制

本分块解决的核心问题是：**把一个在离线数据上训好的大模型，真正安全、实时地跑在物理机器人上。** 四个相对独立的子问题：（a）**延迟与异步执行**——VLA 推理耗时几十到几百毫秒，而控制需要 30–200 Hz，chunk 边界会产生停顿或抖动；（b）**接触与力**——纯视觉看不见力，插拔、擦拭、拧紧类任务必须引入力/触觉；（c）**双臂与全身**——自由度增加带来协调与数据采集难题；（d）**安全**——从物理安全（碰撞、力限）到语义安全（不要把毛绒玩具放在灶台上）。

一个结构性事实：**这四个子问题在学术评测中几乎都不被度量**。主流 benchmark 只报告成功率，不报告延迟、接触力峰值、平滑度或安全违规次数，这使得"部署友好性"在论文竞赛中被系统性忽视，也是学术 VLA 与工业落地之间差距的主要来源之一。

未解决的瓶颈：（1）**没有标准的实时性报告口径**（是否含通信、是否含图像预处理、batch 大小）；（2）**触觉传感器不统一**（GelSight / DIGIT / 电容式 / 力矩传感器互不兼容，表示学习难以复用）；（3）**语义安全评测极新**，且几乎全部依赖 LLM 打分，可靠性未知；（4）**端侧部署证据稀少**——绝大多数 VLA 论文在 A100/H100 上测速，很少报告 Jetson 级硬件上的真实表现。

**技术演进链：**

`ACT/chunking（第 3 类，缓解但不解决延迟）→ TinyVLA（缩小模型以降低延迟）→ Real-Time Chunking（不改模型，用推理时算法消除 chunk 边界）→ Mobile ALOHA（把双臂扩展到移动全身的数据与硬件方案）→ Sparsh（触觉表示学习，补上"看不见的力"）→ SafeVLA / ASIMOV（把安全从事后限位变成训练目标与评测维度）`

- **TinyVLA → RTC**：从"把模型做小换速度"转向"**接受延迟、用算法补偿**"——RTC 不需要重训任何模型，把延迟问题变成一个推理时的 inpainting 问题。
- **RTC → Mobile ALOHA**：从单机延迟问题扩展到**全身系统**——移动底盘 + 双臂 14 自由度的同步遥操作与数据采集。
- **Mobile ALOHA → Sparsh**：补上视觉之外的模态——用自监督在多种视触觉传感器上学出通用触觉表示，使力/接触信息可以被下游策略使用。
- **Sparsh → SafeVLA / ASIMOV**：从"能做"转向"**不该做什么**"——SafeVLA 用约束 MDP 把安全写进训练目标，ASIMOV 用"机器人宪法"把语义安全变成可评测的对象。

> - **安全评测**：SafeVLA-Bench（2026）、ForesightSafety-VLA（2026）、HomeSafe-Bench（2026）（**均待核验**）。

| 维度 | 需要确认的问题 | 相关工作 |
